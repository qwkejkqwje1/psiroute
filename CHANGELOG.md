# Changelog

## 2.0.4 — План приоритетных доработок (Стабильность TUN, Пробив ТСПУ в WARP, Авто-тюнинг DPI, Живучесть в шатдауны, QUIC Desync и Балансировка пула)

- **Приоритет 1 — Критично (Стабильность): Динамический MTU и TCP MSS Clamping (`tun.go`, `tun_windows.go`, `tun_other.go`, `tun_util.go`)**:
  - Внедрён динамический расчёт MTU (`effectiveTunMTU`) и безопасного потолка TCP MSS (`effectiveTunMSS`) для каскада `TUN -> WARP (1280) -> Psiphon` (IPv4 MSS `1180`, IPv6 MSS `1160`), устраняющий PMTUD blackhole, «зависания» сайтов после TLS-рукопожатия и обрывы скачивания больших файлов.
  - Реализован перехват пакетов TCP `SYN` и `SYN+ACK` (`clampTCPMSS`) на входе и выходе TUN с перезаписью опции MSS (`kind=2, len=4`) и инкрементальным пересчётом TCP-контрольной суммы по RFC 1624 (`updateTCPChecksum16`).
  - Добавлено динамическое обновление `NLMTU` на адаптере Wintun (`setTunAdapterMTU`) при переключении каскада WARP / Psiphon без разрыва активных соединений.
- **Приоритет 2 — Высокий (Пробив ТСПУ): Автосканер чистых IP Cloudflare и расширение I1–I5 / MASQUE (`warp.go`, `warpi1.go`, `warpbwg.go`, `warptun.go`, `warpsvc.go`)**:
  - Расширена пред-рукопожатная маскировка AmneziaWG 1.5/2.0 до полноценной 5-пакетной цепочки `I1–I5` (`genI1Chain`, `bwgI1..bwgI5`), имитирующей полный цикл установки соединения QUIC v1 Initial + ECH (`0xfe0d`) + 0-RTT + HTTP/3 SETTINGS + MASQUE `CONNECT-UDP` (RFC 9297 / RFC 9221).
  - Реализован параллельный автосканер чистых IP-адресов Cloudflare (`theWarpScanner.Scan` / `EnsureScanned`) по расширенным пулам Anycast/MASQUE (`162.159.192..204.*`, `188.114.96..99.*`, `8.*`) и портам с сортировкой живых узлов по минимальному RTT.
- **Приоритет 3 — Высокий (Автономность): Фоновый авто-тюнинг DPI (`obfs.go`, `desync.go`, `dpitest.go`)**:
  - В `obfsBook` добавлено скользящее окно контроля ошибок и подряд идущих сбоев (`isMethodDegradedLocked`). При росте процента ошибок на текущем методе автоматически выбирается лучший здоровый метод (`bestHealthyLocked`) даже при ранее зафиксированном методе.
  - Реализован неинтрузивный фоновый авто-тюнер (`maybeRunBackgroundAutoTune`), проверяющий контрольные сайты в фоне и переключающий рабочий метод обхода без ручного захода в тест.
- **Приоритет 4 — Средний (Живучесть в шатдауны): Резервная доставка `server entries` и конфигов ECH через DNS TXT и подписанные зеркала (`psi.go`, `fakeip.go`, `dns.go`)**:
  - В `dns.go` добавлены парсер DNS TXT (`parseDNSTXTWire`, `dohLookupTXT`, `lookupDNSTXT`), сборщик многочанковых TXT-записей (`assembleChunkedTXTRecords`) и проверка криптографической подписи Ed25519 (`verifySignedBootstrapPayload`).
  - В `psi.go` реализован аварийный бутстрап `bootstrapEmergencyServerEntries` через DNS TXT и подписанные HTTPS-зеркала при недоступности S3-списков Psiphon.
  - В `fakeip.go` добавлено резервное получение `ECHConfigList` через DNS TXT (`_ech.<host>`) и встроенные резервные профили ECH при фильтрации DNS `HTTPS` (RRType 65).
- **Приоритет 5 — Средний (Скорость UDP/HTTP3): Фрагментация и фейки для QUIC Initial на UDP:443 (`udp.go`, `desync.go`, `tun.go`)**:
  - Реализовано распознавание пакетов QUIC v1/v2 Initial (`isQUICInitial`) и отправка предваряющих UDP-пакетов-обманок с GREASE-версией и пониженным IP TTL (`buildQUICDesyncPackets`, `sendUDPWithQUICDesync`, `writeUDPWithQUICDesync`), ускоряющих запуск HTTP/3 видео и звонков, когда грубая блокировка `BlockQUIC` отключена.
- **Приоритет 6 — Опционально: Пул из 2 параллельных туннелей Psiphon для балансировки скорости скачивания (`psi.go`, `country.go`, `router.go`)**:
  - Реализована потокобезопасная балансировка `Psi.DialBalanced` и `Countries.DialPoolSlot` (Least-Active-Connections + Round-Robin на атомарных счётчиках `activeConns0`/`activeConns1`) между основным и вторичным туннелем при `psiphon.parallel >= 2`.

- **Сохранение выученных параметров `NetworkID` (`psi.go`)**:
  - `NetworkID` привязан к реальному отпечатку сети и меняется автоматически только при смене сети. Автоматические переподключения по проверке связи или скорости больше не сбрасывают `NetworkID`, сохраняя кэш тактик и серверов в `tunnel-core`.
- **Мульти-целевая проверка связи и защита живого трафика (`psi.go`)**:
  - Опрос трёх независимых целей (`www.gstatic.com`, `cp.cloudflare.com`, `connectivitycheck.gstatic.com`); сбой засчитывается только при отказе всех трёх.
  - Проверка доступности прямого интернета перед выводом о падении туннеля, адаптивный интервал опроса (10–90 с) и запрет разрыва туннеля, по которому за последние 15 с шёл трафик.
- **Резервные источники серверов, мягкая замена и диагностика причин (`psi.go`, `web.go`)**:
  - Несколько `RemoteServerListURLs` с `OnlyAfterAttempts: 0, 1, 2` и импорт `server entries` (`POST /api/psiphon/server-entries`).
  - Мягкая замена контроллера (`standby`) без обрыва активных потоков и классификация причин отказа (`no_network`, `no_candidates`, `all_timeout`, `handshake_reset`, `upstream_dead`, `clock_skew`) + `GET /api/psiphon/stats`.

## 1.0.9

Исправление критических ошибок маршрутизации, обфускации DPI и режима TUN, ускорение DNS и улучшения интерфейса.

- **Маршруты «блок» и «авто» в правилах.** В 1.0.3–1.0.8 в выпадающем списке маршрутов правила были доступны пункты «блок» (`block`) и «авто» (`auto`), но маршрутизатор отправлял такие соединения напрямую (`direct`), а при включённом `failover` переводил заблокированные сайты в Psiphon (UDP при `block` тоже уходил в Psiphon). Теперь правило с маршрутом `block` немедленно блокирует TCP (SOCKS5 код отказа 2 `connection not allowed by ruleset`, HTTP `403 Forbidden`) и UDP без обходных попыток, а правило с маршрутом `auto` проходит по цепочке автоподбора (`auto_chain`) с учётом выученных сайтов.
- **Списки IP и подсети (CIDR) для доменов и режима TUN.** Раньше правила с `CIDR` и IP-списками (`telegram-ip`, `antifilter-ip`) проверялись только тогда, когда программа обращалась по голому IP-адресу. Если был известен домен (из SOCKS5, HTTP `Host`, TLS SNI или обратного DNS в режиме TUN), проверка по подсетям и IP-спискам пропускалась. Теперь маршрутизатор сопоставляет правила и списки одновременно по имени домена и по известным IP-адресам (из заголовка пакета TUN и из кэша DNS).
- **Запоминание SNI при блокировке прямых подключений по IP.** Если соединение было открыто по IP-адресу, но внутри TLS `ClientHello` передавалось доменное имя (SNI) и соединение было сброшено ТСПУ, Psiroute теперь запоминает маршрут не только для IP, но и для самого домена из SNI.
- **Исправлена гонка `Read` и `Write` в `obfsConn` (`direct-dpi`).** При проксировании (`relay`) чтение из сокета запускается параллельно с записью и часто стартовало раньше отправки `ClientHello`. Из-за этого таймер молчания сервера (`obfsFirstByte`, 6 с) не взводился, и при «тихом» дропе пакета на ТСПУ соединение зависало вместо прозрачного повтора следующим методом. Теперь дедлайн первого байта взводится сразу после отправки `ClientHello` (и при каждом повторе), а если `Write` переоткрыл сокет другим методом, ожидающий `Read` прозрачно переключается на новый сокет.
- **Безопасный поиск заголовка `Host` в `obfsHTTP`.** Поиск `\r\nHost:` переведён на побайтовое ASCII-сравнение без аллокаций вместо `bytes.ToLower`, который на многобайтовых UTF-8 символах в URL мог сместить индекс разреза.
- **Кэш DNS-ответов (DoH wire-format) и быстрое закрытие DNS-потоков в TUN.** Повторные DNS-запросы через режим TUN и UDP-туннель теперь берутся из памяти (до 2048 записей, TTL 2 мин, с подстановкой `Transaction ID` запроса) и сбрасываются при смене сети или очистке кэша DNS. В режиме TUN UDP-сокеты DNS закрываются через 2 с после ответа вместо 30 с, а домен из TLS SNI сразу записывается в обратную таблицу `IP → домен` (`revMap`) для последующих UDP-потоков к тому же адресу.
- **Горячая перезагрузка настроек TUN.** Исправлена потеря секции `tun` при перечитывании `psiroute.json` (`reloadConfig`), переключение `tun.enabled` в файле теперь включает или выключает адаптер на лету.
- **Самопроверка, отчёт и трей.** В самопроверку (`--selftest` и кнопка в настройках) добавлена проверка режима TUN и актуализировано сообщение о правах администратора. В `state.json` диагностического отчёта добавлены состояния `tun` и `obfs`. В меню значка в трее добавлен переключатель «Режим TUN (весь ПК)».

# 1.0.7

Надёжность и разбор проблем: Psiroute сам поднимается после сбоя, пишет журнал в файл, умеет проверить себя и собрать отчёт, восстанавливается после сна и смены сети. Плюс UDP через SOCKS5 и правила для отдельных программ.

- Защита от сбоев. psiroute.exe запускает маленький процесс-сторож, а ядро (Psiphon, WARP, прокси) работает под ним. Если ядро упало, сторож выключает системный прокси, если его включало упавшее ядро (браузеры не останутся без интернета), и через несколько секунд запускает ядро снова, свёрнутым в трей. После трёх сбоев за 10 минут перезапуски прекращаются, чтобы не крутиться в цикле. Текст ошибки сохраняется в crash.log, при следующем запуске журнал показывает его первую строку. Ошибка в одном соединении, обработчике интерфейса или фоновой задаче больше не роняет программу: она перехватывается и пишется в журнал, а цикл Psiphon после сбоя перезапускается через 3 с. Сторож занимает пару мегабайт, они видны в строке «Память». Отключить: --no-watchdog (с --no-gui и --pprof сторож не запускается).
- Журнал в файле: psiroute.log рядом с настройками, до 1 МБ, старая часть переносится в psiroute.log.1.
- «Сохранить отчёт» (Настройки): zip в папке «Загрузки» с журналом, crash.log, результатом самопроверки, состоянием и настройками. Пароли, токены и ключи заменяются на ***, ключ WARP (warp-identity.json) в отчёт не попадает. Этот файл можно присылать при любой проблеме.
- Самопроверка: кнопка «Самопроверка» в настройках или psiroute.exe --selftest. Проверяется: сеть, интернет напрямую и через прокси, расхождение часов, UDP через прокси и через Psiphon, системный прокси, автозапуск, WebView2, права, недавние сбои. Если Psiroute уже запущен, --selftest проверяет работающий экземпляр; результат сохраняется в psiroute-selftest.txt.
- Сон и смена сети. Psiroute замечает пробуждение Windows и смену сети (Wi-Fi → кабель, другая точка, VPN): Psiphon переподключается сразу, а не после нескольких минут мёртвого туннеля, кэш DoH сбрасывается. Если сети нет совсем, Psiroute ждёт её появления и не перебирает способы впустую. Проверка здоровья туннеля при неудачном пинге сразу переподключает Psiphon; удачная пишет в журнал «туннель работает (N мс)».
- UDP через SOCKS5 (UDP ASSOCIATE). Режим «UDP через SOCKS5» в настройках: по маршрутам (как TCP того же адреса), всё через Psiphon, напрямую, выключено. Через Psiphon UDP идёт по udpgw внутри туннеля. Помогает только программам, которые сами отправляют UDP через SOCKS5 (звонки Telegram с прокси, Proxifier/ProxyCap, часть игр). Браузеры и Discord так не умеют, для них нужен будущий режим TUN.
- Правила для программ: в правиле маршрута есть поле «программы» (Telegram.exe, chrome; без пути, регистр и .exe не важны). Новая галочка «во всех режимах»: такое правило работает и в режимах «всё через Psiphon» и «авто», раньше запомненных сайтов. Проверка адреса на вкладке маршрутов принимает имя программы.
- Константа иконки перенесена в код для Windows (ложное срабатывание staticcheck в 1.0.6).

# 1.0.6

Память. Из ~200 МБ большую часть занимало не ядро, а окно: интерфейс нарисован WebView2 (движок Edge), а это 5–7 процессов msedgewebview2.exe. Окно было частью ядра, а его закрытие завершало Psiroute, поэтому эта память была занята всё время работы. Правки 1.0.5 касались только ядра и поэтому почти не были заметны.

- Окно — отдельный процесс. Ядро (Psiphon, WARP, прокси) работает со значком в трее, окно открывается щелчком по значку. Закрытое окно завершается вместе со всеми процессами WebView2 и освобождает их память, Psiphon продолжает работать. При первом закрытии окна появляется подсказка.
- Значок в трее: цвет — состояние (зелёный — подключено, синий — подключение, красный — ошибка, серый — отключено), в подсказке — страна выхода и занятая память, меню по правой кнопке: Открыть, Подключить/Отключить Psiphon, Системный прокси, Выход.
- Автозапуск (--minimized) показывает значок в трее; раньше Psiroute работал без окна и без значка.
- Повторный запуск psiroute.exe открывает окно работающего экземпляра. Если значок в трей не добавился (нет панели задач), закрытие окна завершает Psiroute, как раньше.
- WebView2 запускается облегчённым: без запасного процесса отрисовки, один процесс отрисовки на страницу, без SmartScreen и фоновых загрузок. Фон до загрузки страницы — по теме Windows, без белой вспышки.
- Освобождённая память возвращается системе: раз в 20 с, если у Go накопилось от 4 МБ свободной кучи, она отдаётся Windows (раньше процесс минутами держал пиковый размер). Это и GOGC=50 теперь работают и в процессах стран и проверки обхода DPI.
- Сколько памяти занято и где: внизу боковой панели («Память: …», подробности при наведении), в подсказке значка и в /api/state (mem).
- При выключении Windows или выходе из учётной записи системный прокси выключается сразу (настройка сохраняется и применяется при следующем запуске). Раньше после перезагрузки браузеры до запуска Psiroute смотрели на закрытый порт.
- Журнал: больше не показывается «close tunnel ssh error … use of closed network connection» — это закрытие лишнего туннеля после подключения, а не ошибка.

# 1.0.5

Только то, что помогает подключиться к серверам Psiphon, и то, что делает программу легче. Из ProxyDesk взят только WARP-минимум для Psiphon; AWG, MASQUE, SSH-выходы, пул узлов и отдельный процесс-помощник не переносились.

- WARP встроен. При включённом WARP способ «Через WARP» идёт первым: Psiphon подключается изнутри WireGuard-туннеля к Cloudflare, провайдер видит WARP, а не Psiphon. Бесплатное устройство WARP регистрируется само (warp-identity.json).
- Начало соединения WARP маскируется: пакет I1 похож на QUIC (HTTP/3) или DNS-запрос, за ним идут мусорные пакеты («Маскировка WARP»: Авто, QUIC, bash-warp-generator, DNS, выкл.; «Авто» перебирает и запоминает рабочую). Узлы Cloudflare за российским и белорусским фильтром (DME, SVX, KJA, OVB, KZN, MSQ) пропускаются. Если сеть обрывает UDP-поток, туннель переподключается новым потоком.
- Без лишних программ: туннель работает внутри psiroute, поднимается только когда Psiphon идёт через WARP, и закрывается после 10 минут простоя. Внешний WARP SOCKS5 по-прежнему можно выбрать («Какой WARP» → внешний SOCKS5).
- Psiphon: первый круг по способам быстрый: 45 с на способ, затем 90 и 180 с. Запоминается только способ, на котором туннели продержались 3 минуты. Способ, туннели которого сеть рвёт в первые 2 минуты дважды подряд, уходит в конец списка на 6 часов.
- Кнопки «Следующий способ» и «Новый узел»: нажатие раньше чем через 20 с после предыдущего (или после начала попытки) не обрывает текущую попытку, интерфейс показывает, сколько подождать.
- Легче: процесс Psiphon для отдельной страны гасится после 5 минут простоя (было 15).
- Ошибки чтения больше не теряются молча (подбор обхода, процессы стран, списки адресов) — найдено go vet.

### Маршрутизация
- IP-адреса в правилах совпадают только точно; пустой шаблон ни с чем не совпадает; точка в конце имени игнорируется.
- Порты в правиле объединяются с доменами по «И». Ключевые слова не зависят от регистра. CIDR разбирается один раз, одиночный IP считается /32.
- Выученные маршруты применяются только в режиме «авто». Срок жизни — 14 дней, лимит — 2000 записей, счётчик обращений растёт при использовании.
- Выученные маршруты сохраняются атомарно и не чаще раза в 2 с; при выходе они записываются на диск.
- SOCKS5 к внешнему прокси: проверка длины полей, IP передаётся как ATYP 1/4.
- Для `https://`-прокси используется TLS, код ответа разбирается правильно.

### Прокси
- Обычный HTTP: одно соединение — один запрос (`Connection: close`). Раньше keep-alive отправлял запрос к другому сайту в чужой апстрим.
- Пароли сравниваются за постоянное время.
- Перебираются до 3 IP-адресов; DNS разрешается один раз на соединение.
- Блокировка DPI определяется только по RST или по закрытию со стороны сервера. Закрытие со стороны клиента (preconnect, закрытая вкладка) больше не учит неверные маршруты.
- Корректные коды ответа SOCKS5, полузакрытие соединения при передаче данных.

### Windows
- Прежние настройки системного прокси сохраняются и восстанавливаются при отключении; в исключения добавлен `[::1]`.
- Таблица TCP кэшируется на 500 мс, имена процессов — на 1 минуту.

### Прочее
- API без токена отвечает 403. Токен сравнивается за постоянное время, тело запроса ограничено 1 МБ, тексты ошибок переведены на русский, заголовок Content-Type в ошибках исправлен.
- DNS: проверка HTTP-статуса DoH, отрицательный кэш на 30 с, лимит кэша, запись в журнал при переходе на системный DNS.
- Статистика: одинаковый ключ хоста при открытии и закрытии, лимит размера таблицы.
- Раздача в LAN по умолчанию требует пароль.
- Интерфейс не опрашивает сервер, пока окно свёрнуто.
