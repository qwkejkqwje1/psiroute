# ТЗ: тестирование Psiroute 1.0 (Go)

Исполнитель: ИИ-агент или разработчик с доступом в интернет и к Windows 10/11 (x64). Цель — собрать программу, исправить ошибки сборки, проверить **работоспособность, скорость и лёгкость** и сдать отчёт по шаблону из раздела 9.

## 0. Правила
- Не менять архитектуру и интерфейс. Исправлять только ошибки сборки, баги и явные проблемы производительности. Каждое исправление — отдельный коммит с пояснением.
- Все цифры — измеренные, не оценочные. Каждый замер повторить 3 раза и указать медиану.
- Если пункт выполнить нельзя, написать в отчёте «не проверено» и причину.

## 1. Сборка и статический анализ
1. Go 1.23+. В папке проекта выполнить: `go mod tidy`, `go vet ./...`, `staticcheck ./...` (honnef.co/go/tools).
2. Сборка Windows: `go build -ldflags "-H windowsgui -s -w" -o psiroute.exe .`. Сборка для тестов: `go build -race -o psiroute-race.exe .` (без -H windowsgui, чтобы был виден вывод).
3. Кросс-проверка: `GOOS=linux go build .` должна проходить (файлы *_other.go).
4. Записать: размер exe, время сборки, все исправленные ошибки компиляции.

## 2. Модульные тесты (написать `*_test.go`, без сети)
| Что | Проверки |
|---|---|
| `hostMatches` (router.go) | точный домен, поддомен (`a.b.com` против `b.com`), `*.`-шаблоны, регистр, IP, пустые строки |
| `Router.plan` | режимы psiphon / rules / auto; приоритет выученных сайтов; failover добавляет psiphon в конец; совпадение правила по порту |
| `remember / forget / clearLearned` | сохранение в файл и загрузка обратно, счётчик hits |
| `parseSNI` | реальный ClientHello (TLS 1.2/1.3 — взять дампы из crypto/tls), обрезанный пакет, не-TLS данные |
| desync.go | после разреза ClientHello склеивается в исходные байты; разрез приходится внутрь SNI |
| proxy.go | SOCKS5: без авторизации, логин/пароль, неверный пароль, IPv4/IPv6/домен; HTTP CONNECT и обычный HTTP; `isPrivateAddr`; `proxyAuth.lanFree` |
| config.go | `defaultConfig`; `setKey` для каждого ключа из `values()` и правильный флаг restart; битый JSON не затирает настройки (reloadConfig) |
| dns.go | кэш на 5 минут, `clear()`, гонки (`-race`) |
| psi.go | `applyDPI` для всех 5 режимов (значения из README ProxyDesk), `configFor` даёт валидный JSON для каждой стратегии, `cleanPsiErr` |
| stats.go | `tick`, суточная история, корректная сумма байт при 100 параллельных соединениях |
| share.go | `qrSVG` даёт валидный SVG; `shareInfo` формирует правильные ссылки socks5:// и t.me |

Требования: покрытие пакета ≥ 60 % (`go test -cover`), `go test -race ./...` проходит без замечаний.

## 3. Интеграционные тесты (локально, без Psiphon)
Поднять в тесте фейковые upstream-серверы: echo-TCP, HTTPS (`httptest.NewTLSServer`), SOCKS5.
1. Режим rules: правило направляет домен на direct, остальное — на фейковый «proxy»-upstream. Проверить по логу и статистике, что трафик ушёл куда надо.
2. Failover: первый выход сбрасывает соединение, проверить переход на следующий за ≤ 7 с и запись в выученные сайты.
3. **Имитация DPI:** написать middlebox на Go (TCP-прокси), который рвёт соединение (RST/close), если видит SNI `blocked.test` целиком в одном TCP-сегменте. Проверить: direct не проходит, direct-dpi проходит, в auto-режиме сайт выучивается.
4. Web API: без заголовка `X-Psiroute` → 403; Host `evil.com` → 403; `/api/ping` доступен без токена; все эндпоинты из web.go отвечают корректным JSON.
5. Горячая перезагрузка psiroute.json: правка правила применяется ≤ 4 с; битый файл — предупреждение в логе, старые настройки остаются.
6. Повторный запуск exe не создаёт второй экземпляр, а открывает окно первого.
7. Раздача в сеть: вход с другого IP без пароля отклоняется, с паролем — проходит.

## 4. Сквозные тесты с Psiphon (реальная сеть)
1. Чистый первый запуск: время от старта до состояния connected. По каждой стратегии (auto, meek, tls, quic, ossh) — 5 запусков, медиана и максимум.
2. Кнопки «Сменить узел», «Следующая стратегия», смена страны (DE, NL, US): время переподключения, страна выхода совпадает с выбранной (cdn-cgi/trace).
3. Автоподбор обхода: завершается ≤ 8 мин, ранжирование разумное, «Применить» действительно меняет стратегию или режим DPI.
4. Обрыв сети (отключить адаптер на 30 с): программа восстанавливается сама, без ручных действий.
5. Если есть доступ к сети с блокировками (РФ, мобильный оператор): проверить каждый режим DPI и записать, какие подключаются.
6. Системный прокси: включить и выключить; после «Выход» и после убийства процесса через диспетчер задач. **Во втором случае прокси не должен остаться включённым без работающей программы** — если остаётся, это баг, предложить исправление (например, сброс при следующем запуске).

## 5. Производительность и лёгкость (главное)
Профилирование: запускать с `--pprof 127.0.0.1:6060`, снимать `/debug/pprof/heap`, `goroutine`, `profile?seconds=30`.

| Метрика | Как мерить | Цель |
|---|---|---|
| Размер exe | после `-s -w` | ≤ 40 МБ |
| Запуск до окна | секундомер или ETW, холодный и тёплый запуск | ≤ 1,5 с (тёплый) |
| RAM в простое, connected | Private Bytes в Process Explorer; parallel=1 + standby=off, затем значения по умолчанию (2 + standby) | ≤ 80 МБ / ≤ 120 МБ |
| CPU в простое | среднее за 5 мин | < 1 % |
| Накладные расходы на скорость | iperf3 или загрузка 100 МБ через Psiroute и через «голый» Psiphon (официальный клиент или ProxyDesk) на том же узле | потеря ≤ 5 % |
| Задержка локального прокси | 1000 соединений к локальному echo через direct: p50/p99 разницы с прямым подключением | p99 ≤ 2 мс |
| Нагрузка | 500 одновременных соединений (браузер + скрипт), 10 мин | без ошибок, CPU < 30 % |
| Утечки | 4 часа обычного серфинга + скрипт, открывающий и закрывающий соединения | рост RAM < 10 %, число горутин возвращается к исходному |
| Фоновый трафик | счётчик адаптера за 1 час простоя | ≤ 5 МБ/ч |
| Отзывчивость интерфейса | открыть каждую вкладку при 500 соединениях | без подвисаний > 200 мс |

Сравнить те же метрики с Psiroute v0.5 (Rust + psiphon.exe — считать оба процесса вместе) и ProxyDesk, если их можно собрать.

## 6. Удобство (UX-чеклист)
- Первый запуск: сколько кликов до работающего VPN (цель — 1 кнопка или ноль при автостарте).
- Понятно ли без документации: куда идёт трафик, какой узел и страна сейчас, как сменить узел или страну, как включить обход DPI.
- Ошибки показываются по-русски и с подсказкой, что делать (а не стек-трейс).
- Окно на экранах 1366×768 и 4K (масштаб 150 %): ничего не обрезается.
- Сравнить с v0.5: что стало удобнее, что хуже.

## 7. Безопасность
- API и UI слушают только 127.0.0.1; раздача в сеть — только когда включена.
- Нет утечки DNS при включённом DoH (Wireshark: нет UDP/53 на системный DNS для direct-соединений).
- Токен не попадает в лог.
- Пароль раздачи генерируется криптостойко.
